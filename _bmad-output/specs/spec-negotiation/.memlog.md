- (direction) Slug: negotiation. Spec covers Milestone 1 (deterministic core) of Parley: buyer/merchant negotiation protocol, merchant policy schema, state machine, audit log schema. No LLM negotiation logic and no Razorpay integration in this milestone (later milestones).
- (capability) CAP-1 intent: merchant-agent evaluate(offer, policy, round) determines accept/counter/reject citing the policy field that drove the decision. success: unit tests over below-min-price, over-max-discount, in-bounds, and each qty_break tier all return the correct decision and evidence_paths.
- (capability) CAP-2 intent: a negotiation loop drives buyer-agent and merchant-agent through rounds to a deterministic terminal state. success: every run terminates within max_negotiation_rounds in exactly one of AGREEMENT_RECORDED, REJECTED (explicit), or REJECTED (round-limit).
- (capability) CAP-3 intent: every negotiation action is recorded as a structured, hash-verifiable JSONL audit entry. success: audits/negotiation.log has one parseable JSON object per line per action; decision_hash recomputed from offer+rationale+evidence_paths matches the logged value.
- (constraint) Merchant-agent decision logic (evaluate()) must be pure, deterministic, rule-based Python with no LLM or network calls in Milestone 1; LLM-based negotiation is a later milestone.
- (constraint) Negotiation rounds are hard-capped at policy.max_negotiation_rounds (default 5 per AGENTS.md); exceeding it without agreement forces terminal state REJECTED, never an unbounded loop.
- (constraint) Every accept/counter/reject decision must cite evidence_paths: dotted paths into the policy object (e.g. policy.min_price, policy.qty_breaks[1].discount_pct, policy.max_negotiation_rounds) identifying exactly which policy field drove the decision. A decision without evidence_paths is invalid.
- (constraint) Razorpay/payment API calls are out of scope for Milestone 1; the audit schema reserves decision_hash and provenance_sha fields for later payment-milestone use but implements no payment call.
- (non-goal) No LLM-based negotiation logic in Milestone 1 -- deterministic rule-based only.
- (non-goal) No real or test-mode Razorpay API integration in Milestone 1 -- payment settlement is a later milestone.
- (non-goal) No TRANSACTION_APPROVAL_THRESHOLD human-approval workflow in Milestone 1 -- approval gating ships alongside payment integration.
- (non-goal) No multi-SKU / multi-item cart negotiation in Milestone 1 -- one product/SKU per merchant_policy.json only.
- (assumption) Currency is INR: Razorpay is India-focused and PROJECT_GUIDANCE.md left currency an open question with only a numeric threshold (5000) stated.
- (assumption) qty_breaks entries define the maximum discount_pct allowed at that quantity tier, OVERRIDING (not stacking with) the policy's base max_discount_pct; the highest min_qty tier the offer's qty meets or exceeds applies.
- (assumption) Merchant counter-offer price is deterministic: max(min_price, list_price * (1 - applicable_discount_pct_at_offer_qty)) -- the most generous price permitted under policy at the buyer's requested qty. Counter keeps the buyer's requested qty unchanged.
- (assumption) offer.terms is a free-form string reserved for future milestones, unexamined by Milestone-1 merchant logic; offer.expiration and audit timestamp are ISO 8601 UTC strings.
- (assumption) provenance_sha in audit entries uses the literal placeholder "UNVERIFIED" for Milestone 1 (no git-based provenance wiring yet), matching the precedent already set in AGENTS.md's own provenance line.
- (assumption) Milestone 1 negotiates a single product/SKU per merchant_policy.json; the policy's product identifier is a plain string sku_id.
- (assumption) decision_hash = sha256 hex digest of UTF-8 canonical JSON (json.dumps with sort_keys=True, separators=(',',':')) of {"offer": offer, "rationale": rationale, "evidence_paths": evidence_paths} -- deterministic and independently recomputable from the three logged fields.
- (assumption) Buyer-agent's scripted opening offer and split-the-difference concession strategy (per user direction) is a Milestone-1 test-harness implementation detail, not part of the cross-milestone negotiation contract; it is not pinned in SPEC.md/companions.
- (decision) Why: competition mandate (Razorpay AI Buildathon, Agentic Commerce track) requires a buyer-agent and merchant-agent that negotiate under merchant-defined constraints and transact end-to-end, explainably. This spec covers the negotiation contract; a mandate to meet (competition deliverable) plus a vision to realize (agentic commerce workflow).
